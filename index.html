01 / 概览

产品定位与适用场景

麦播链（MicSpeakLink）是一套电脑端 + 手机端协同的局域网音频方案， 通过 WebRTC 在内网建立低延迟双向链路，再叠加本地 ASR 引擎实现语音转文字。 整个链路不依赖公网服务器，语音数据不离开你的局域网。

图 1 · PC 端软件首页 — 深色 Audio Console 风格的主控面板， 集中展示设备连接、模式切换、ASR 状态、语音音量与识别文本。

适合什么用户

  • 无麦无喇叭的台式主机用户，不想额外购置 USB 声卡或蓝牙耳机。
  • 需要本地实时语音转写，做会议记录、口述文档、聊天输入。
  • 对延迟敏感，嫌弃蓝牙耳机打游戏开会影音不同步。
  • 对隐私敏感，不希望语音上传到任何第三方云服务。
  • 多设备切换用户，希望手机随手当麦克风 / 扬声器用。

02 / 双模式

写模式 vs 听模式

麦播链提供两个互斥的音频工作模式，由后端统一状态机裁决。 同一时刻只能启用其中一个，避免音轨冲突。

✎
WRITE MODE ASR 文字注入
写模式
Speak → Type

把手机麦克风采集的语音，实时转发到 PC 端做离线语音识别， 识别出的文字直接发送到当前桌面输入框的光标位置。

音频链路

手机麦克风 → WebRTC 上行 → PC 解码 → Sherpa-ONNX 模型 → 文本注入 → 桌面输入框

典型场景

  • 对着手机口述，自动输入到 Word / 记事本 / IDE / 聊天窗口
  • 会议记录、长文写作、邮件草稿
  • 无障碍输入、临时替代键盘

前置依赖

  • ASR 模型文件已就绪（首次启动会自动下载/校验）
  • PC 默认输入设备已指向 VoiceMeeter Input
  • 桌面焦点处于可输入控件
♪
LISTEN MODE 音频回传 VoiceMeeter
听模式
System Audio → Phone

把 PC 端的系统播放音频通过 VoiceMeeter Banana 抓取， 经 WebRTC 下行到手机扬声器播放，让手机充当电脑的外放喇叭。

音频链路

PC 系统音频 → VoiceMeeter Banana → WASAPI Loopback → Opus 编码 → WebRTC 下行 → 手机扬声器

典型场景

  • 没有外接音箱的台式机，需要外放声音
  • 半夜看电影 / 听歌，不开音响也不戴耳机
  • 把手机放到任何位置听电脑音频（沙发、厨房、阳台）

前置依赖

  • 已安装并运行 VoiceMeeter Banana
  • PC 默认输出设备已指向 Voicemeeter AUX Input
  • VoiceMeeter 路由：VoiceMeeter Input → B1 / Voicemeeter AUX Input → B2
★

模式互斥原则：写模式和听模式不能同时开启。 切换任何一个模式时，另一个会被后端自动停用。这种设计由 store.toggleListenMode() / store.toggleListening() 统一裁决，避免 UI 与真实状态错位。

能力流对比图

写模式 · Speak → Type

手机 Mic → WebRTC → PC ASR → 文本注入 → 桌面输入框

听模式 · System Audio → Phone

PC 系统音频 → VoiceMeeter → Loopback → Opus → WebRTC → 手机扬声器
03 / 安装

PC 端与手机端安装

麦播链由两个端组成：Windows 电脑端负责系统集成与 ASR， Android 手机端负责拾音和外放。两端必须在同一局域网。

3.1 PC 端安装步骤

图 2 · 安装向导欢迎页 — NSIS 安装包启动后展示的欢迎界面， 默认勾选安装路径、桌面快捷方式与 ASR 模型集成。
1
下载 PC 端安装包
从 GitHub 仓库 github.com/tengyuangangben/MicSpeakLink 的 Releases 页面获取 MicSpeakLink-Setup-v0.1.0.exe。该安装包已内置 ASR 模型、WebView2 离线运行时与 VoiceMeeter 协同安装逻辑。
2
以管理员身份运行安装器
右键 → 以管理员身份运行。安装器会写入注册表、注册 mDNS 服务、调度 VoiceMeeter 检测逻辑。 非管理员权限可能导致 VoiceMeeter 路由配置失败。
3
同意安装路径并完成安装
默认安装到 %LOCALAPPDATA%\Programs\MicSpeakLink。 安装过程中如果检测到系统未安装 VoiceMeeter Banana，会自动弹出 VB-Audio 安装器， 等待 GUI 窗口关闭后安装器会复检注册表并自动路由。
4
首次启动并查看首页
安装完成后会自动启动麦播链，首次启动会校验 ASR 模型完整性。 进入首页后即可看到设备面板、模式切换开关、识别文本区。
图 3 · PC 端软件首页 — 启动后主控面板， 显示设备 ID、配对码生成、模式开关、信任设备管理、运行时状态。

3.2 获取安装包（统一入口）

i

统一下载入口：请前往麦播链的 GitHub 仓库 github.com/tengyuangangben/MicSpeakLink 的 Releases 页面，同时获取 PC 端安装包（.exe）与 Android 端安装包（.apk）。 Releases 页面会按版本号罗列每个版本的官方构建产物及校验信息，请勿从第三方渠道下载，以免被植入恶意代码。

3.3 手机端安装步骤

1
下载 APK
从上述 GitHub Releases 页面下载最新版本的 MicSpeakLink-v0.1.0.apk 到手机本地存储。 可用手机浏览器打开仓库地址直接下载，也可先下载到电脑再通过 USB / 微信文件传输 / 网盘等方式拷贝到手机。
2
开启「未知来源安装」并安装 APK
系统设置 → 应用 → 特殊应用权限 → 安装未知应用 → 选择你的浏览器/文件管理器 → 允许。 然后点击 APK 完成安装。首次启动会申请麦克风和通知权限，请全部允许。
图 4 · 手机 APP 首页 — Android 端深色 Audio Console 风格首页， 包含麦克风采集卡、连接状态指示、远端音频状态卡与历史字幕区。
3
授予自启动和电池白名单（可选但推荐）
为保证切到后台时音频流不中断，建议按系统提示把麦播链加入： ① 自启动白名单 ② 电池优化白名单 ③ 后台运行白名单。 华为/小米/OPPO/vivo/三星 ROM 路径各不相同， APP 首次进入主页会弹出引导，可按提示一键跳转。

3.3 端到端配对（手机输入配对码连接 PC）

麦播链通过局域网自动发现 + 配对码认证建立手机与 PC 的 WebRTC 链路。 不是扫码，而是手机端手动输入 PC 端显示的 6 位数字配对码完成配对。

1
确认 PC 端已启动麦播链
PC 端麦播链必须处于运行状态（托盘有图标，首页可访问）。 此时首页会显示一个 6 位数字配对码（每 60 秒自动刷新）。 记住或复制该配对码，手机端马上要用。
2
打开手机 APP，点击右上角的「刷新」按钮
APP 启动后默认在扫描页。点击页面右上角的刷新按钮主动触发一次局域网扫描， 否则会等待下一轮自动扫描。扫描过程会遍历 1~254 子网内的 mDNS / 端口探测， 一般 2~5 秒内出结果。
3
在扫描列表中点击你的电脑 IP
扫描结果会列出所有在局域网里、且 PC 端麦播链已启动的设备，每条带电脑名称与 IP。 点击你要连接的那台 PC（需要与 PC 端首页显示的电脑名一致），APP 会跳转到配对页。 如果列表为空，确认两端在同一 Wi-Fi 且路由器未开启 AP 隔离。
4
在配对页输入 PC 端显示的 6 位配对码，点击「连接」
配对页提供 6 个独立输入框用于输入配对码，逐位填写即可。 填写完成后点击页面下方的 「连接」 按钮提交认证。 若配对码已过期（PC 端 60 秒倒计时归零），系统会提示重新生成。
5
等待连接成功，自动进入写模式
认证通过后 APP 会自动完成 WebRTC 协商与音频通道建立，约 1~3 秒进入主页。 主页默认就处于写模式开启状态，手机麦克风采集的语音会被实时识别并下发到 PC 端。 若首页右下角未显示「已连接 [电脑名]」，请重试步骤 2~4。
图 5 · 手机端连接成功后的界面 — 显示电脑名称、连接状态、实时音量波形、识别字幕历史。 连接成功后默认即处于写模式，无需在手机端额外切换。
★

信任设备机制：首次配对成功后，手机会以加密形式把 device_token 存到本地。 下次打开 APP，已信任的 PC 会自动显示「已信任」标记，连接时跳过配对码输入步骤， 直接进入主页并默认开启写模式。

04 / 写模式

写模式完整配置

写模式需要 PC 端的 ASR 模型、Windows 默认输入设备、以及桌面输入焦点三者就绪。 以下按步骤完成配置。

4.1 准备 ASR 模型

1
检查 ASR 模型状态
打开 PC 端麦播链，在首页查看 模型状态指示：
  • 就绪（绿点）：模型完整加载，可直接使用。
  • 下载中（琥珀色 + 进度环）：首次启动自动下载 ZipFormer 中英双语模型（~120 MB）。
  • 未就绪（红点）：模型文件缺失或损坏，需重新下载。
2
手动下载或校验模型（如需）
进入 设置页 → 模型管理，点击「重新下载模型」即可触发。 模型完整性由 SHA256 校验，下载失败可重试。
模型落盘位置：%APPDATA%\com.micspeaklink.app\resources\models\zipformer-bilingual\
!

踩坑提示：正式发布的 PC 安装包必须带 --features asr 编译选项， 否则会退回 Mock 引擎 —— 模型开关亮着但实际不识别。 下载第三方构建版本时请确认是 官方 release。

4.2 配置 Windows 默认输入设备

写模式启动后，PC 端 ASR 会通过 WASAPI 共享模式读取名为 VoiceMeeter Input 的虚拟输入设备。 因此 Windows 默认输入设备必须指向它，否则 ASR 拿不到音频。

方法一：键盘快捷键（推荐）

1
按下 Win + I 打开 Windows 设置
任意界面下同时按下 Win 键和 I 键，唤起 Windows 系统设置窗口。
2
在左侧导航中选择「系统」
系统设置首页包含显示、声音、通知、电源等子项。
3
滚到最下方选择「声音」
进入声音设置页，可以看到输出、输入、声音设备三块区域。 关于「Win + I → 系统 → 声音」入口的完整图示请参见 第 5.3 节「输入 / 输出设备的统一入口」。
4
向下滚动到「输入」区域，把默认设备改成 VoiceMeeter Input
在「选择你的输入设备」下拉框中，选择 VoiceMeeter Input。 这一步把系统默认输入指向虚拟麦克风。
图 7 · Windows 默认输入设备配置 — 红色框内为「输入」区域， 在「选择你的输入设备」下拉框中选择 VoiceMeeter Input。
5
验证输入条在说话时会跳动
对着手机说话时，下方「测试你的麦克风」进度条应当明显跳动。 如果完全不动，请检查手机 APP 是否处于已连接状态， 以及麦克风权限是否被授予。

方法二：右下角任务栏一键切换

  • 右键点击任务栏右下角扬声器图标 → 选择「声音设置」。
  • 或在弹出的设备列表里直接切换「默认输入设备」。

4.3 在麦播链中开启写模式

1
确保手机端已连接
确认手机 APP 已显示「已连接 [电脑名]」，且 Pulse 状态点为绿色脉冲。 否则写模式开启后无法获取音频。
2
PC 端切换到写模式
首页 → 「写模式」开关拨到右侧。开关亮起琥珀色表示 ASR 已开始接收音频。 首次启动时后端会自动加载模型，加载期间会显示「正在初始化」提示。
3
PC 端用鼠标点击激活目标输入框
把 PC 鼠标移动到任意可以输入文字的地方（浏览器地址栏、Word、记事本、聊天窗口、IDE 编辑区等）， 用鼠标点击该输入框，让光标（闪烁的竖线）落在控件内。 麦播链会把识别结果写入光标所在位置，因此这一步必不可少。
4
按下 Ctrl + Shift + Space，开始语音输入
按下默认全局快捷键 Ctrl+Shift+Space（可在设置页自定义）后， 写模式开关会切到「录制中」状态，手机麦克风采集的语音会被实时识别并下发到 PC 端， 片刻后文字就会直接出现在你刚才点击的输入框光标处。 再次按下同一快捷键即可停止录入。
★

快捷键推荐用法：每次需要录入文字时， ① 先用鼠标点击目标输入框（让焦点落在那里）， ② 再按下 Ctrl+Shift+Space 开麦说话， ③ 讲完后再次按下同一快捷键（或自动停止）， 识别出的文字就会插入到你当前所在的文本框。 切换到下一个输入框时重复 ①②③ 即可。

4.4 全局快捷键

快捷键动作
Ctrl + Shift + Space开始 / 停止语音录入（写模式主快捷键）
Ctrl + Shift + L切换听模式（音频回传开 / 关）
Ctrl + Shift + W写模式开关（与首页 UI 同步）
i

关于快捷键冲突：如果你安装了其他同样使用 Ctrl+Shift+Space 的软件， 可以在 PC 端设置页 → 快捷键中重新绑定或禁用。 快捷键需在麦播链 PC 端启动时生效。

05 / 听模式

听模式完整配置

听模式依赖 VoiceMeeter Banana 虚拟音频设备。 如果你的 PC 在安装麦播链时已经安装了 VoiceMeeter，可直接跳转第 5.2 节。

5.1 确认 VoiceMeeter Banana 已运行

1
查看 PC 端首页的 VoiceMeeter 状态
首页会显示三种状态：
  • NotInstalled：未安装，需手动下载 VoiceMeeter Banana 并安装。
  • Installed：已安装但未运行，请双击桌面 VoiceMeeter Banana 图标启动。
  • Running：已运行，听模式可用。
2
首次安装或升级 VoiceMeeter
运行 VB-Audio 安装器，按默认选项完成安装。 安装完成后重启一次 Windows 让虚拟音频驱动生效。 启动 VoiceMeeter 主窗口（不要关闭），确认右下角托盘出现 mixer 图标。

5.2 配置 Windows 默认输出设备

听模式启动时，麦播链会自动把 Windows 默认输出设备切换为 Voicemeeter AUX Input，以便 PC 的所有应用声音都进入虚拟链路。 你也可以手动按下面的方式切换。

1
按下 Win + I 打开 Windows 设置
任意界面下同时按下 Win + I。
2
选择「系统」→「声音」
进入声音设置页。
3
向下滚动到「输出」区域，把默认设备改成 Voicemeeter AUX Input
在「选择你的输出设备」下拉框中，选择 Voicemeeter AUX Input。 完成后系统所有应用声音都会进入 VoiceMeeter 链路。
图 8 · Windows 默认输出设备配置 — 红色框内为「输出」区域， 在「选择你的输出设备」下拉框中选择 Voicemeeter AUX Input。

5.3 输入 / 输出设备的统一入口

「默认输入」（VoiceMeeter Input，写模式使用）与 「默认输出」（Voicemeeter AUX Input，听模式使用） 都在 Windows 设置的同一个声音页面里管理。 所有相关配置都从此处进入，写模式需要切换输入设备、听模式需要切换输出设备时，都按下面方式打开：

  1. 按下 Win + I 快捷键，打开「Windows 设置」窗口。
  2. 在左侧导航栏中点击「系统」，向下滚动找到并点击「声音」。
图 9 · 设置 → 系统页面 — 左侧选中「系统」，向下滚动找到「声音」入口。 进入后即可在同一页内分别配置「输出」（听模式）和「输入」（写模式）默认设备。
!

重要提示：VoiceMeeter 未运行时，Voicemeeter AUX Input 与 VoiceMeeter Input 都不会出现在下拉框中。请先按 第 5.1 节 启动 VoiceMeeter 主窗口，再来此处切换。

5.4 VoiceMeeter 自动路由

麦播链会在听模式启动时调用 vm_remote.rs 自动配置 VoiceMeeter 路由， 固定为：

输入输出总线作用
VoiceMeeter InputB1手机麦克风上行（写模式音频流）
Voicemeeter AUX InputB2PC 系统音频下行（听模式音频流）
★

自动化说明：上述路由由 Remote API 全自动写入， 不需要你手动在 VoiceMeeter GUI 里拖线。 如果你想保留自定义路由，可以在设置页关闭「自动路由」开关。

5.5 在麦播链中开启听模式

1
确保手机端已连接
手机 APP 已显示「已连接」，Pulse 状态为绿色。
2
PC 端首页 → 打开「听模式」开关
开关亮起蓝色（info 色）表示下行链路建立成功。 后端会自动切换默认输出设备到 Voicemeeter AUX Input 并写入路由。
3
调整手机音量
使用手机系统音量键控制外放音量。 PC 端的播放音量不影响链路，可以保持中等以避免回授。
06 / FAQ

常见问题与处理

按出现频率整理了 15 个常见问题，每个问题都给出症状 / 原因 / 处理步骤三段式答案。

Q1. 安装时弹出「需要管理员权限」怎么办？

症状：双击安装包后立即弹出 UAC 提示被拒绝，或安装器直接退出。

原因：麦播链需要写注册表（mDNS 服务声明）、写入 VoiceMeeter 路由配置、注册全局快捷键，这些操作都要求管理员令牌。

处理：

  • 右键安装包 → 「以管理员身份运行」。
  • 如果 UAC 始终拒绝，请联系 IT 部门申请本地管理员权限。
  • 便携模式（不需要管理员）当前版本不提供。
Q2. 模型状态一直显示「下载中」或「未就绪」？

症状：首页模型指示灯长时间红色或黄色。

原因：模型文件缺失、SHA256 校验失败、磁盘空间不足或网络受限。

处理：

  • 设置页 → 模型管理 → 重新下载。
  • 确认 %APPDATA%\com.micspeaklink.app\resources\models\zipformer-bilingual\ 目录有 1 个 encoder + 1 个 decoder + 1 个 joiner + 1 个 tokens.txt。
  • 查看首页底部日志区是否提示「网络超时」「磁盘已满」。
  • 如使用代理，请在系统设置 → 网络 → 代理中配置。
Q3. 写模式开启后，对着手机说话 PC 没有识别文字？

症状：写模式开关亮起，手机端音量条跳动，但 PC 端没有任何文本输出。

原因：通常有以下几种 ——

  • Windows 默认输入设备没有指向 VoiceMeeter Input。
  • 桌面焦点不在可输入控件（如焦点在桌面图标区）。
  • ASR 引擎被全局快捷键暂停，或模型处于 Mock 引擎（构建版本不带 asr feature）。

处理：

  • 按本文 第 6.2 节 检查默认输入设备。
  • 把光标移到记事本/浏览器地址栏等可输入处再试一次。
  • 首页 → 引擎类型应当显示为 SherpaOnnx，如显示 Mock 请重新下载官方安装包。
Q4. 听模式开启后，手机扬声器没有声音？

症状：听模式开关亮起，但手机无声。

原因：通常是 VoiceMeeter 没运行、Windows 默认输出没切、或 B2 总线被关闭。

处理：

  • 确认 VoiceMeeter Banana 主窗口已打开（不要最小化到托盘）。
  • 按本文 第 6.3 节 检查默认输出设备。
  • 打开 VoiceMeeter GUI，确认 AUX Input → B2 处于「开」状态。
  • 手机系统音量是否过低？检查是否被静音。
  • 关闭麦播链听模式后再开一次，让 vm_remote 重新写入路由。
Q5. 手机端扫描不到电脑？

症状：APP 扫描页面长时间转圈，没有出现电脑列表。

原因：两端不在同一局域网、或路由器禁止了 5353 / 9870 等端口的 mDNS 广播。

处理：

  • 确认手机和电脑连接到同一个 Wi-Fi（不是访客网络）。
  • 电脑端首页查看 deviceId 是否已生成；如有，但手机扫不到，请关闭电脑防火墙临时验证。
  • 企业网/校园网经常屏蔽组播，请改用手机热点临时验证。
  • 如路由器开启了 AP 隔离，请关闭。
Q6. 配对码输入后一直「连接中」？

症状：手机端输入配对码后转圈超过 30 秒仍未连接。

原因：配对码已过期（默认 60s）、输入错误、或 PC 端 mDNS 服务异常。

处理：

  • PC 端首页查看配对码倒计时是否已结束 —— 是的话点击「刷新配对码」。
  • 重新输入，注意区分大小写与易混字符（0/O、1/I/l）。
  • 关闭并重开 PC 端麦播链，再生成新配对码。
Q7. WebRTC 连接频繁断开？

症状：连接成功几秒到几十秒后自动断开，循环往复。

原因：路由器切换信道、手机省电策略杀进程、防火墙阻断 STUN/TURN。

处理：

  • 把麦播链手机 APP 加入电池白名单与自启动。
  • Wi-Fi 信号差时改用 5 GHz 频段，或靠近路由器。
  • 检查路由器是否启用了「Wi-Fi 省电」「设备隔离」等功能。
  • 避免一边使用一边进行大文件下载（占用同一 AP 带宽）。
Q8. VoiceMeeter 列表里找不到 VoiceMeeter Input / AUX Input？

症状：Windows 声音设置下拉框中没有 VoiceMeeter 设备。

原因：VoiceMeeter 没安装 / 安装后未重启 / 驱动未注册。

处理：

  • 从 VB-Audio 官网 下载 Banana 版本（不是 Potato）。
  • 安装完成后重启 Windows，让驱动注册。
  • 打开 VoiceMeeter 主窗口至少一次，让虚拟端点初始化。
  • 设备管理器 → 声音、视频和游戏控制器 下应当出现 VB-Audio VoiceMeeter Input / Output。
Q9. 手机切换 Wi-Fi 后连接断开，能自动恢复吗？

症状：从公司 Wi-Fi 回到家 Wi-Fi（或反之）后连接断开。

原因：IP 变化后 mDNS 缓存失效 + WebRTC ICE 重协商。

处理：

  • 在手机 APP 扫描页手动点击「重新扫描」。
  • 已信任设备列表会自动尝试用 device_token 重新认证，无需重新输配对码。
  • 如手机为 IPv6 网络 + 电脑为 IPv4 网络，请在路由器开启 NAT64 或统一为 IPv4。
Q10. 识别文字出现错字或漏字？

症状：识别的文字与原话有偏差。

原因：环境噪声、说话含糊、麦克风增益过低、口音与训练集差异。

处理：

  • 手机麦克风对准嘴部，距离 10~20 cm。
  • 在安静环境使用，关闭空调/风扇等持续噪声源。
  • 语速放慢、吐字清晰是关键。
  • 当前模型为中英双语，识别中英混合表现更佳。
Q11. 全局快捷键不生效？

症状：按下 Ctrl+Shift+W 没有反应。

原因：被其他软件占用、未授予后台快捷键权限、麦播链未启动。

处理：

  • 确认麦播链 PC 端正在运行（托盘有图标）。
  • 检查是否有其他软件（截图工具、IDE）占用同一快捷键。
  • 设置页 → 快捷键 → 修改为不冲突的组合。
Q12. 写模式 + 听模式可以同时开吗？

答：不能。

麦播链的两个模式由统一状态机裁决，互斥运行。 切换其中一个，另一个会被后端自动停用。 这是设计约束，避免音轨冲突与 ASR / Loopback 抢占资源。

如果你既需要 ASR 又需要听到电脑声音，可：

  • 先用写模式完成语音输入，再切回听模式听音频。
  • 或直接在手机上接一副耳机，听模式时声音走耳机，写模式时说话走手机麦。
Q13. 安装包被杀毒软件拦截？

症状：双击安装包后 Windows Defender / 火绒 / 360 立即删除或隔离。

原因：未签名的安装包被启发式引擎误判，或下载源不在信任列表。

处理：

  • 从官方 GitHub Release 或 docs/release/ 目录下载。
  • 将安装包加入杀毒软件白名单。
  • 右键安装包 → 属性 → 勾选「解除锁定」后再运行。
Q14. 手机端后台运行几分钟后音频就停了？

症状：APP 切到后台 1~5 分钟后再回来，没有识别也没有声音。

原因：手机系统杀掉了麦克风 / 前台服务 / WebSocket。

处理：

  • 首次进入主页时按系统弹窗引导，把麦播链加入自启动 + 电池白名单。
  • 不同厂商 ROM 路径：
    • 华为/荣耀：手机管家 → 应用启动管理 → 麦播链 → 改为「手动管理」并全部勾选。
    • 小米/红米：安全中心 → 自启动管理 + 电量与性能 → 后台配置 → 麦播链 → 无限制。
    • OPPO/realme：设置 → 电池 → 更多电池设置 → 关闭「睡眠待机优化」；设置 → 应用 → 应用管理 → 麦播链 → 自启动 + 关联启动。
    • vivo：设置 → 电池 → 后台高耗电 → 麦播链 → 允许。
    • 三星：设置 → 应用程序 → 麦播链 → 电池 → 后台使用限制 → 改为「不优化」。
  • 开启 APP 内的「前台服务保活」开关（如有提示）。
Q15. 在哪里查看日志 / 提交 Bug？

症状：遇到无法解决的问题，需要排查或上报。

处理：

  • PC 端日志：%APPDATA%\com.micspeaklink.app\logs\app.log.YYYY-MM-DD。
  • 手机端日志：APP 内 → 设置 → 导出运行日志。
  • GitHub Issue：项目仓库的 Issues 页面，提供两端日志、复现步骤、系统版本、设备型号。
  • 诊断信息：PC 端首页 → 设置 → 导出诊断包（含 ASR 状态、VoiceMeeter 状态、设备拓扑）。

7.2 配置任务清单

  • Windows 10/11 + Android 7+ 已就绪
  • PC 安装包来自官方 release 渠道
  • 手机 APK 已开启「未知来源」
  • 两端连接同一 Wi-Fi（同子网或 AP 互通）
  • VoiceMeeter Banana 已安装并启动
  • 默认输入 = VoiceMeeter Input
  • 默认输出 = Voicemeeter AUX Input
